# Meal Planner — Plan 4: Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Getting recipes in from outside: a recipe inbox fed by mail (Cloudflare Email Worker) and pasted URLs;
parent-only processing (links → schema.org Recipe → AI on page text → AI on mail text and screenshots) into a
reviewed draft; AI translation of recipes into German; AI usage limits and a usage log.

**Architecture:** Backend modules: `mail.py` (headers + MIME structure only on arrival; full decode only when
processing), `inbox_api.py` (inbound endpoint, inbox list/discard/attachments/thumbnails, URL items, process,
drafts), `fetch.py` (safe HTTP fetch with SSRF guard and size limits), `jsonld.py` (schema.org Recipe → draft),
`ingredient_parse.py` (ingredient lines → amount/unit/name/note), `ai.py` (Infomaniak client, fake client, rate
limit, usage log, recipe and translation prompts, answer validation), `importer.py` (the processing pipeline, run in
a background task). Frontend: `Inbox` page, draft review in `RecipeEdit`, originals and translation on
`RecipeView`, settings sections for mail addresses and AI usage. Worker: copied from family-budget-dashboard.

**Tech Stack:** as Plans 1–3; Python stdlib `email`, `urllib`, `html.parser`, `ipaddress`; Cloudflare Worker
(TypeScript, Vitest), copied.

**Spec:** `docs/superpowers/specs/2026-10-29-meal-planner-design.md` — "Getting recipes in", "AI", "Language",
anti-goals. **Builds on:** Plans 1–3 (`api_error`, `require_parent`, `config`, `Recipe` + `RecipeIn` +
`recipes_api.recipe_out`, `photos.store_photo`, `units.UNITS`, locales, `RecipeEdit`, `RecipeView`, `WeekHeader`).

## Global Constraints

- **Nothing from a mail is decoded, fetched or sent to the AI before a parent releases it** ("Verarbeiten"). On
  arrival only headers and the MIME structure are read (sender, subject, date, attachment names/types/sizes).
  Links in the text part are listed **when processing**, not on arrival (this tightens the spec's "builder's call").
  Thumbnails of image attachments are made on the NAS when a parent opens the inbox (no AI, no network).
- Mail accepted only from an address registered for a family member (`user_emails`); otherwise 403
  `inbound_sender_unknown`. Secret header `X-Inbound-Secret` = `INBOUND_SECRET` (constant-time compare); empty
  secret → 503 `inbound_off`. Max raw mail 25 MB → 413 `inbound_too_big`. Same `Message-ID` twice → stored once.
- A URL item pasted by a **parent** is processed at once (the paste is the release); by a child it waits.
- Children see only their own inbox items and can't process or discard; parents see all.
- Every AI call: parent only; counts against `AI_CALLS_PER_HOUR` per user (default 30, `0` = off) → 429
  `ai_limit` with `minutes`; logged in `ai_calls` (user, time, purpose `import`|`translate`, item/recipe id, tokens if
  reported). No `INFOMANIAK_AI_TOKEN`/`INFOMANIAK_AI_PRODUCT_ID` → AI off (`ai_off`, 503); the link/JSON-LD route
  still works. Model `AI_MODEL`, default `google/gemma-4-31B-it`. `AI_FAKE=1` → fake client (e2e only).
- The AI answer is untrusted: parsed as JSON, validated against the draft shape (units mapped to `UNITS` or null,
  amounts > 0 or null, strings trimmed and length-capped), never executed or rendered as HTML.
- Fetching: only `http`/`https`, ports 80/443, every resolved address must be public (no loopback, private,
  link-local, multicast, reserved — checked for each redirect hop, max 5), 10 s timeout, 3 MB max body, `text/html`
  or `application/ld+json` only; `User-Agent: Mozilla/5.0 (Menüplaner; family use)`.
- Draft shape (what processing produces, what the review screen edits): `RecipeIn` fields + `uncertain: list[str]`
  (short texts like "200 g oder 250 g Mehl?") + `image_index: int | null` (which mail image to use as photo) +
  `source_url`.
- Originals kept per imported recipe: the inbox item stays (status `done`, linked `recipe_id`) with its raw mail,
  URL and raw AI answer; the recipe view links "Original ansehen".
- Translation (parent, AI): `POST /api/recipes/{id}/translate` → German text for title, ingredient names and notes,
  steps, notes; amounts/units untouched; the previous text is stored in `recipes.original` (JSON) unless already set;
  `language` becomes `de`. `GET` returns `original` so the view can toggle "Original anzeigen".
- Error codes (new, with texts in both locales — `tests/test_error_texts.py` enforces it): `inbound_off`,
  `inbound_wrong_secret`, `inbound_too_big`, `inbound_sender_unknown`, `item_not_found`, `item_busy`,
  `attachment_not_found`, `not_a_web_link`, `ai_off`, `ai_limit`, `ai_failed`, `nothing_found`, `email_taken`,
  `invalid_email`, `already_german`, `draft_not_ready`.

## Review Focus

1. **A mail from an unregistered address, or a forged one** → refused, nothing stored; the worker rejects it (no silent loss). Test in Task 1 (backend) and Task 7 (worker, copied tests).
2. **A link in a mail pointing into the home network** (`http://192.168.1.1/`, `http://nas.local`, a public name resolving to 10.x, a redirect to 127.0.0.1) → never fetched. Test in Task 3.
3. **A child pastes 20 URLs or mails 20 recipes** → nothing is processed and no AI is called until a parent clicks; a parent clicking "process" 31 times in an hour gets `ai_limit` with the minutes to wait. Test in Task 2 and Task 4.
4. **The AI answers garbage** (prose, half JSON, units like "cups", 50 000 ingredients, `<script>` in a step) → `ai_failed` or a sanitized draft; never a 500, never HTML. Test in Task 4.
5. **Processing takes 40 s** (AI + several screenshots) → the request returns at once, the item shows "wird verarbeitet…", the page polls; a second click doesn't start it twice (`item_busy`); a restart of the backend mid-way leaves the item retryable (status back to `waiting` with an error after 10 minutes stuck). Test in Task 5.

### Task 5: Processing pipeline and drafts

**Files:** Create `importer.py`, `tests/test_importer.py`; Modify `inbox_api.py`, `recipes_api.py` (`POST /api/recipes` accepts `inbox_item_id` and `image_index`)

**Interfaces:**
- `POST /api/inbox/{id}/process` (parent) → 202 `InboxItemOut` with `status: processing`; `item_busy` (409) if already processing (unless stuck > 10 min); starts `importer.start(item_id, user_id)` via FastAPI `BackgroundTasks` (runs in the thread pool with its own DB session).
- `importer.process(db, item, user)`:
  1. **Links** (URL item: its URL; mail: links from the text/HTML part, first 3, Facebook/Instagram links skipped since they give nothing without login) → `fetch` → `jsonld.recipe_from_html` → draft (no AI). Photo: `image_url` fetched through `fetch` (image types allowed for this call, 10 MB) and stored with `photos.store_photo` → `draft.photo` name.
  2. **AI on page text** if a page was fetched but had no JSON-LD: page text (HTML → text via `html.parser`, scripts/styles dropped, ≤ 20 000 chars) → `take_call` → `recipe_from_ai`.
  3. **AI on the mail**: text part (≤ 20 000 chars) + all image attachments → `take_call` → `recipe_from_ai`; `draft.image_index` from the AI (or the first image).
  4. Nothing usable → status `failed`, `error: nothing_found`; AI errors → `failed` + code (`ai_failed`, `ai_limit`, `ai_off`).
  Success → status `draft`, `draft` stored, `ai_raw` stored.
- `GET /api/inbox/{id}` → `InboxItemOut` + `draft`.
- `POST /api/recipes` with `inbox_item_id` → creates the recipe (`source_kind` from the item, `source_url`), copies the photo (`draft.photo`, or the mail image `image_index` through `photos.store_photo`), marks the item `done` with `recipe_id`. Only for items in `draft` status.
- `RecipeOut` gains `inbox_item_id: int | None` (the item that produced it) for the "Original ansehen" link.
- Stuck guard: an item `processing` for more than 10 minutes counts as failed (`error: ai_failed`) on the next read.
