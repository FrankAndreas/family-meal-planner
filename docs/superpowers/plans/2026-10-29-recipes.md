# Meal Planner — Plan 2: Recipes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The family's recipe collection: create, edit, view (scaled to the number of people), photos, tags, per-person
ratings and favourites, parent-only soft delete, search.

**Architecture:** New backend modules `recipes_api.py` (CRUD, list/search, ratings, favourites, photo),
`scaling.py` (pure scaling and rounding — the shopping list in a later version reuses it), `units.py` (the fixed
unit list), `photos.py` (store/convert images). Scaling happens **only in the backend**: the recipe view asks
`GET /api/recipes/{id}?people=N`. Frontend gets three pages (list, view, edit) and a small `amounts.ts` for parsing
typed amounts, tested with Vitest.

**Tech Stack:** as Plan 1, plus Pillow 13 + pillow-heif 1.8 (iPhone HEIC photos), Vitest for frontend pure functions.

**Spec:** `docs/superpowers/specs/2026-10-29-meal-planner-design.md` (sections "Recipes", "Scaling", "Later")
**Builds on:** Plan 1 (`docs/superpowers/plans/2026-10-29-foundation.md`): `auth.get_current_user`, `auth.require_parent`,
`errors.api_error`, `settings_store.get_settings`, `config.data_dir()`, `ui.ts` classes, locales, e2e helpers
(`newPerson`, `login`, `API`, `PIN`).

## Global Constraints

- Everyone may create and edit recipes, rate and favourite (their own); **only parents delete**, and deleting is a
  soft delete (`deleted_at`), so history (Plan 3) keeps the name.
- Recipe language is kept as imported (`language` field, `de`|`en`|null); the UI language does not change it.
- Units: a fixed list of keys (below). Unknown unit → 422 `unknown_unit`. Labels come from the locales.
- Yield: `servings` (> 0, ≤ 100) + `servings_unit` (null = people; else a free word like "Blech", "Stück", ≤ 30 chars).
- Scaling: factor = `people / servings` when `servings_unit` is null; otherwise `people / family_size`.
  Ingredients without an amount are never scaled.
- Error codes (new): `recipe_not_found` (404), `unknown_unit` (422), `photo_unreadable` (400), `photo_too_large` (413).
- Photos: JPEG, EXIF orientation applied then **all metadata dropped** (no GPS), longest side ≤ 1600 px, max upload
  25 MB, stored at `data/photos/<uuid4>.jpg`. Served without login at `/api/photos/<uuid>.jpg` (unguessable name; the
  app is only reachable at home — the tunnel exposes `/api/inbound` only).
- All new visible text in `locales/{de,en}.ts`.

### Units (key → de label / en label)

`g` g/g · `kg` kg/kg · `ml` ml/ml · `dl` dl/dl · `l` l/l · `tsp` TL/tsp · `tbsp` EL/tbsp · `pinch` Prise/pinch ·
`piece` Stk./pc · `clove` Zehe/clove · `slice` Scheibe/slice · `bunch` Bund/bunch · `can` Dose/can · `cup` Becher/pot ·
`pack` Pck./pack · `handful` Handvoll/handful

### Rounding after scaling (`scaling.round_amount(amount, unit)`)

| unit | rule |
|---|---|
| `g`, `ml` | < 10 → nearest 1; < 100 → nearest 5; < 1000 → nearest 10; else nearest 50 |
| `kg`, `l` | nearest 0.05 below 1, else nearest 0.1 |
| `dl` | nearest 0.5, at least 0.5 |
| `tsp`, `tbsp` | nearest 0.25 below 1, else nearest 0.5; at least 0.25 |
| `pinch` | nearest 1, at least 1 |
| `None`, `piece`, `clove`, `slice`, `bunch`, `can`, `cup`, `pack`, `handful` | nearest 0.5, at least 0.5 |

"At least" applies only to amounts > 0. Halves round half up (`2.25 → 2.5` for counted units).

## Review Focus

1. **Amounts typed on an iPad with a Swiss keyboard** ("0,5", "1/2", "1 1/2", "½") → parsed to 0.5 / 0.5 / 1.5 / 0.5; garbage ("abc") is refused in the form, not sent as `null` silently. Test in Task 4 (Vitest) and Task 5 (e2e).
2. **A photo straight from an iPhone** (HEIC, 4032×3024, EXIF rotation and GPS) → accepted, upright, ≤ 1600 px, no EXIF left. Test in Task 3.
3. **"Vegi" and "vegi" as tags** → one tag; the tag filter lists it once. Test in Task 1.
4. **A deleted recipe opened by a link or from history** → still readable (`deleted: true`), never in the list or search. Test in Task 1.
5. **Scaling a "1 Blech" recipe for 2 people with family size 4** → factor 0.5; a recipe for 4 people opened for 0 or 101 people → 422, not a division error. Test in Task 2.
