# "Was habe ich?" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search the family's own recipes by the ingredients at home, in two modes (Aufbrauchen / Jetzt kochen), with
an editable list of basics that always count as at home.

**Architecture:** A pure matching module (`backend/app/pantry.py`) decides whether a typed word matches an ingredient
name. A new router (`backend/app/use_up_api.py`) ranks live recipes with it and serves ingredient-name suggestions.
The family settings get a `staples` list. The Rezepte page gets a second view, "Was habe ich?", with a chips input
that the Settings page reuses for the basics.

**Tech Stack:** FastAPI, SQLAlchemy + Alembic (SQLite), pytest; React 19 + TypeScript + Tailwind, i18next, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-01-use-up-design.md`

## Global Constraints

- Only the family's own recipes: no internet, no AI in this feature.
- Case and accents never matter: normalize with `sort_key` from `backend/app/recipes_api.py`.
- A false ✓ is worse than a miss (spec anti-goal): when in doubt, don't match.
- Default basics, in this order: `["Salz", "Pfeffer", "Öl", "Wasser", "Zucker", "Mehl", "Bouillon"]`.
- Jetzt kochen shows recipes with **at most 2** missing and at least 1 used.
- Basics are edited by parents only (`auth.require_parent`, as `PATCH /api/settings` already is); every role may search.
- Visible text only from `frontend/src/locales/{de,en}.ts` (`npm run lint` runs `check-texts`). German: «», no ß, "du".
- Paths: new API under `/api/use-up` and `/api/ingredient-names`. Not under `/api/recipes/…`, where
  `/recipes/{recipe_id}` (int) would answer 422.
- Run backend tests with `venv/bin/python -m pytest`; frontend `cd frontend && npm run type-check && npm run lint && npm test`;
  e2e `cd e2e && E2E_PYTHON=../venv/bin/python HUB_PYTHON=../../family-hub/.superpowers/venv/bin/python npx playwright test`.

## Review Focus

1. A recipe made only of basics (Salz, Wasser): it appears only when a typed word matches one of them, and then
   that word is in `used`. Basics alone never make a hit → test in Task 3.
2. The same typed word twice, or two typed words that are synonyms (Rahm + Sahne): counted once in "used" → Task 3.
3. Typed words with surrounding blanks, empty strings, or 30 chips: blanks ignored, empty ignored, a cap of 20 `have`
   values (422 above) → Task 3.
4. An ingredient name typed all lowercase ("kartoffeln, festkochend"): still matches. The noun-only rule must not
   drop everything → Task 1.
5. localStorage blocked (private mode): the view still works, it just forgets → Task 4 (try/catch around every
   access; no test, review only).

- [ ] **Step 3: Implement `backend/app/pantry.py`**

The algorithm (the tests don't determine it, so this is the decision):

1. **Ingredient words:** drop text in brackets; split on anything that isn't a letter. If the original name has
   any capitalized word, keep only capitalized words (German nouns; drops "festkochend", "mehlig", "rote"). Otherwise
   keep all words. Normalize each with `sort_key`.
2. **Base form** `base(word)`: strip the first matching ending of `("en", "er", "n", "e", "s")` if at least 2 letters
   remain (Tomaten/Tomate → tomat, Eier → ei, Kartoffeln → kartoffel).
3. **Synonyms:** `SYNONYMS: list[set[str]]` of base forms, at least: kartoffel/hardopfel/erdapfel, rahm/sahn,
   ruebli/karott/mohr (Möhre), quark/topf (Topfen), zucchetti/zucchini, peperon/paprika, nusslisalat/feldsalat.
   A typed word expands to its whole group. `canonical(word)` returns the group's first member, or `base(word)`.
4. **Match** of one typed base `t` against one ingredient word base `w`:
   - equal, or
   - **head:** `w` ends with `t` and the part before is at least 3 letters (Halb|rahm yes; R|ei, Br|ei no), or
   - **start** (not strict): `len(t) >= 4` and `w` starts with `t` (Lauch|stange yes).
5. **Exceptions** `EXCEPTIONS: dict[str, tuple[str, ...]]`, keyed by typed base, with the compound starts that make a
   different food. At least: lauch → knob, schnitt, bar; kartoffel → suss; zwiebel → fruhlings; milch → kokos;
   butter → erdnuss; ei → br, salb (covers Hirse**brei**, Gries**sbrei**, Sal**bei**). A head match is refused when
   the part before `t` ends with one of these. Extend if the tests need it; keep the list with the synonyms.

- [ ] **Step 4: Run the tests until they pass**

Run: `venv/bin/python -m pytest tests/test_pantry.py -q`. Expected: all pass. Adjust the algorithm, not the tables.
Only if a table row truly contradicts another, note it in the commit message.

### Task 3: Search API

**Interfaces:**
- Consumes: `pantry.matches`, `pantry.canonical`, `recipes_api.live_recipes`, `recipes_api.Votes`, `recipes_api.sort_key`,
  `settings_store.get_settings(db).staples`
- Produces:
  - `GET /api/use-up?have=Kartoffeln&have=Lauch&mode=use_up|cook_now` → `list[schemas.UseUpOut]`.
    `UseUpOut(RecipeSummary)` adds `used: list[str]` (the typed words as typed, in typed order, one per synonym

  - `GET /api/ingredient-names?q=kar` → `list[str]`: distinct ingredient names (as written, first spelling wins
    when names differ only in case or accents) of live recipes whose `sort_key` contains `sort_key(q)`, the
    ones starting with it first, then alphabetical by `sort_key`, at most 10. Empty `q` → `[]`.
  - Both need a login (`auth.get_current_user`), any role.
