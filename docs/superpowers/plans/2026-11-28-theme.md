# Themes, step 3: meal-planer – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The meal planner uses `family-hub-theme` instead of its own copy of the look, shows the person's theme from
the hub, and has no palette colours left in its components.

**Architecture:** As family-budget-dashboard's step 2 (its plan `docs/superpowers/plans/2026-11-28-theme.md` and PR
#197 are the worked example): the hub's `theme` is stored per person (here a `users.theme` column, as `language`
is one), `/api/me` returns it, `AuthContext` calls `applyTheme`; the CSS imports the package; components use roles.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, pytest; React 19, Vite 8, Tailwind v4, Playwright.

**Spec:** `family-hub/docs/superpowers/specs/2026-11-28-themes-design.md`; package use: `family-hub/theme/README.md`.

## Global Constraints

- Package: `"family-hub-theme": "https://github.com/FrankAndreas/family-hub/releases/download/theme-v1.0.0/family-hub-theme-1.0.0.tgz"`.
- Client: `family-hub-client @ https://github.com/FrankAndreas/family-hub/archive/7a9848864c6fad37f791f8ed0f3d4521c4276936.tar.gz#subdirectory=client` (1.2.0).
- Fewer shades on purpose; before/after screenshots of the main screens in the PR.
- No palette classes, hex codes or `rgba()/hsl()` in `frontend/src/**/*.tsx` (`check-colors.mjs` as in
  family-budget-dashboard, which has the `rgba()` rule); the app's own CSS uses `var(--fh-*)` only.
- Text on solid state fills uses `text-page`; translucent `bg-surface-strong` panels that cover content (dialogs,
  menus, sticky bars, overlays) also get `backdrop-blur-glass` (lesson from the budget review).
- Blur checks in e2e are polled (`expect.poll`), never read once (lesson from family-hub CI).
- The existing Playwright suite (incl. `a11y.spec.ts`, `axe.spec.ts`) passes.

## Review Focus

1. Hub sends no or an unknown theme → `aurora`, no error.
2. Theme changed in the hub → next `/api/me` after the app's hub cache returns it.
3. Overlays and sheets (formerly `bg-black/50`, `bg-slate-900/90…95`) still cover and dim; nothing shows through.
4. Cyan and fuchsia used as decoration (tags, chips, gradients) keep a visible difference to plain text.
5. Selected vs unselected (plan days, chips, filters) stays distinguishable after `bg-white/5`/`/10` fold into
   `hover`/`pressed`.
